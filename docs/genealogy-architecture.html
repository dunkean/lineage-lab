LINEAGE LAB / TECHNICAL GUIDE

From a scenario to a world of recorded lives

The application is a standalone Python population sandbox. Configuration, simulation, storage and exploration are separate layers. No LLM, external service or map engine is required.

1. Validated inputs

config.py validates a versioned scenario: seed, years, demographic and social rules, ancestry profiles, settlements, politics and dated crises. Explicit maps are accepted; otherwise virtual profiles generate a seeded spatial layout.

Presets and web assets travel inside the Python package. A wheel installed outside its source checkout has the same built-in scenarios.

2. Annual simulation

Existing unions → births → mortality and union closure → divorces and new unions → household migration → year-end census

The initial census is at the starting year. Births and deaths can share a year. The alive marker is separate from calendar values, so negative years are valid. Founder parents and earlier residence histories remain unknown rather than being invented.

Population regulation uses one run: mortality enforces an enabled ceiling, while bounded fertility recovery supports the floor. Crises can still push the world below that floor. The ceiling is a limit, not a growth promise.

3. State and events

engine.py stores dense IDs and contiguous NumPy columns. Numba kernels handle matching and selected reductions. Known-ancestry checks remain enabled at scale. Union and migration events are kept in binary buffers alongside birth/death and family fields.

The memory backend keeps the studio ephemeral. Explicit persistence writes a fresh SQLite archive. Full-mode compact export packs fields for efficient storage and indexed reading. Existing archive markers remain stable.

4. Two population contracts

FullHybrid
Every person is simulated; family events are recorded.A detailed core is simulated once; background cohorts store counts.
Historical people remain available back to the founders.Ordinary families are projected deterministically when requested.
Memory grows with historical people and events.Background exploration is limited to two ancestor and five descendant generations.

Hybrid is not a compressed replay of the full engine. Background families have documented restrictions; core and background do not exchange partners. Source labels distinguish recorded and procedural people.

5. A common read interface

archive_protocol.py exposes overview, people, ancestry, descendants, residents, residence, maps and distributions. The local server routes those operations to memory, SQLite, compact or hybrid readers. Opaque hybrid IDs must remain unchanged.

The studio runs one background generation job. It keeps the active world and two recent alternatives. Archive-specific reads prevent one browser tab from silently changing another tab's world. Cancellation does not publish an incomplete result.

6. What the model does not establish

Parameters are fiction choices, not historical calibration. Founder ancestry before the simulation is unknown. Display names remain placeholders. Dynamic settlement founding, arbitrary retrospective hybrid promotion and full-mode worlds of fifty million people over a millennium are not established capabilities.

See the user guide, hybrid contract and historical measurement notes alongside this file for commands and explicit approximations. The test suite checks family/event invariants, replay, storage parity, politics, regulation and the standalone package boundary.
